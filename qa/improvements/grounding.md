# 현재 구조

## Overview

현재 앱은 서버나 npm 런타임 의존성이 없는 Chrome MV3 확장이다. 패널이 UI, 작업 큐, 데이터를 모두 소유하고 페이지에 직렬화한 함수를 주입하여 YouTube DOM과 Notebook 내부 RPC를 읽는다. 서비스 워커는 패널 열기 설정만 한다.

## Key Concepts

영상과 선택 여부만 chrome.storage.local의 videos 키에 저장한다. 각 패널은 초기 한 번 읽고 자체 saveQueue로 전체 배열을 쓴다. 저장 변경 구독이 없어 다른 패널의 변경을 덮어쓸 수 있다.

노트북, 소스 목록, 본문, 추출 상태는 패널 메모리만 소유한다. 본문을 영속 저장하지 않는 것이 기존 개인정보 설계다. 완료 상태와 본문 보유 여부가 결합되어 재추출 실패 시 기존 본문을 내보내는 정책을 표현하지 못한다.

## How It Works

수집은 시작 시 탭 ID만 고정한다. 최대 45회 읽기, 병합, 스크롤, 대기를 반복한다. 같은 탭에서 검색어나 채널을 바꾸면 자료가 섞일 수 있다.

Notebook 읽기는 MAIN world에서 페이지의 인증 정보를 요청 내부에만 사용한다. 목록은 rLM1Ne, 본문은 hizoJc 요청이다. 요청당 25초 제한이 있다. 429를 일반 오류 문자열로 변환하므로 대기열은 중지되지 않는다.

소스 목록 갱신은 동일 노트북 URL과 소스 ID의 본문과 done 상태를 보존한다. 추출은 done 항목을 건너뛰고 세 요청을 동시에 실행한다. 중지는 실행 중 요청이 끝난 뒤 새 요청 시작을 막는다.

## Where Things Live

| 파일 | 책임 |
| --- | --- |
| extension/core.js | 정규 URL, 영상 병합, Markdown |
| extension/panel.js | 패널 상태, 저장, 작업 큐, 탭 선택 |
| extension/page-actions.js | 독립적으로 직렬화할 두 주입 함수 |
| extension/background.js | 패널 열기 설정 |
| tests/core.test.js, tests/notebook.test.js | 순수 로직과 가짜 RPC 검증 |
| tools/mock-chrome.js | UI 검증용 API |

## Gotchas

- 전체 배열을 읽고 병합한 뒤 다시 쓰는 방식만으로는 동시 선택 변경과 삭제 충돌이 해결되지 않는다.
- 재추출은 성공한 뒤 본문을 교체해야 한다. 실패 시 이전 본문 보유와 최신 요청 실패를 동시에 표시해야 한다.
- 일부 소스 행을 해석하지 못해도 전체 실패가 아니면 버린다. 원본 개수와 누락 행을 기록해야 한다.
- 오류를 전달할 때 종류와 재시도 정보를 보존해야 요청 제한을 처리할 수 있다.
- 수집 페이지와 노트북 계정의 동일성을 요청 경계에서 확인해야 한다.
- 노트북 선택은 현재 창의 열린 탭으로 해결할 수 있다.
- 삭제 취소는 이전 배열 전체 복구가 아니라 삭제한 항목 복원이어야 한다.
- 외부 서버, 자동 Notebook 수정, 추가 호스트 권한을 도입하지 않는다.
- 실제 확장 설치와 실제 계정 RPC는 기존 검증에서 빠져 있다.
