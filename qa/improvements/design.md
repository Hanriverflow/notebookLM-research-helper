# 구현 계약

## 선택

설계 B의 단일 작성자 명령을 기본으로 한다. 두 후보와 별도 검토자가 같은 저장 구조를 선택했다. 연산 로그와 재전송 receipt는 추가하지 않는다. 응답이 유실되면 변경 명령을 자동 재전송하지 않고 현재 목록을 다시 읽는다.

별도 검토는 gpt-6.1-terra가 수행했다. 점수는 설계 비교 판단이며 실행 성능 수치가 아니다.

## 데이터와 함수 계약

- Video는 기존 {url, title, channel, selected}를 유지한다. 정규 URL이 식별자다. 추가 id나 metadata 출처 필드는 만들지 않는다.
- LibrarySnapshot은 {revision, videos}다. 내부 저장 envelope는 한 키에서 version, revision, videos, undoRecords를 함께 저장한다.
- VideoCommand는 read, add(items), enrich(items), select(urls, selected), delete(urls), undo(token)이다. 모든 명령은 저장소 하나에서 처리한다.
- Source는 기본 정보, selected, lastSuccess: null 또는 {text, extractedAt}, attempt: {state, error?}를 갖는다. 본문 존재와 최신 요청 상태를 분리한다.
- Notebook은 현재 식별 정보와 context, reportedCount, omissions를 갖는다. omission은 {rowIndex, title, reason}이며 항상 화면과 Markdown 누락 절에 포함한다.
- composeMarkdown(notebook, sources, date)는 기존 호출 형태를 유지하되 Source의 새 상태를 사용한다. 호출자와 테스트를 함께 바꾼다.
- 주입 결과는 기존 {error: message}에 code와 retryAt를 추가해 오류 종류를 보존한다. 성공 목록은 notebook, sources, omissions, reportedCount를 반환한다.

## 저장과 삭제

새 모듈 video-store.js가 저장 schema, 명령 검증, 직렬 큐, 클라이언트 구독을 소유한다. 공개 형태는 createVideoCommandHandler(storage), connectVideos(api, onSnapshot)로 한다. connectVideos는 ready, command, dispose를 제공한다. background는 모듈로 전환해 listener를 동기적으로 등록하고 비동기 응답에는 return true를 사용한다.

기존 videos 배열은 새 키가 없을 때 한 번 가져온다. 새 키가 있으나 손상되었으면 명시적으로 오류를 낸다. 저장 성공 전 UI 성공을 표시하지 않는다. 패널은 onChanged를 먼저 구독하고 첫 snapshot을 요청한다. 이벤트와 응답은 revision이 더 클 때만 적용한다. 패널의 전체 배열 저장 경로는 제거한다.

선택과 삭제는 명시된 URL만 변경한다. 전체 비우기도 클릭할 때 알고 있던 URL을 삭제한다. undo는 실제 삭제한 항목만 복원하고 현재 항목과 동시 추가를 보존한다. 토큰은 5분, 최대 최근 10회이며 한 번만 소비한다. 같은 URL을 새로 추가하면 과거 undo 기록의 그 URL을 무효화한다. 용량 때문에 복구하지 못한 수를 알린다.

수집 작업은 처음 본 URL을 한 번 add하고 이후 라운드는 enrich한다. 그래야 다른 패널에서 삭제한 영상을 반복 수집이 되살리지 않는다. 기존 유효 제목과 선택을 유지하면서 URL 제목과 빈 채널만 채운다. 500개여도 기존 항목의 metadata는 보완한다.

## 추출과 페이지 문맥

fresh는 선택한 모든 정상 소스, retry는 본문이 없거나 최근 시도가 실패 또는 취소된 소스다. 성공 시에만 lastSuccess를 교체한다. 실패나 중단 시 이전 본문을 보존한다. 이전 본문을 내보내면 추출 시각과 갱신 실패 또는 중단을 명시한다. 누락만 있어도 보고서를 저장할 수 있다.

소스 목록의 모든 행을 정상 소스 또는 omission으로 분류한다. 중복 ID도 omission으로 남긴다. reportedCount는 정상 소스 수와 omission 수의 합이다. 외부 제목, URL, 채널 자료형을 경계에서 제한한다. RPC 원문과 인증 정보를 반환하지 않는다.

기존 동시 요청 3개를 유지한다. 첫 429를 확인하면 job 전체의 대기 요청 시작을 멈춘다. 이미 시작한 최대 2개는 완료될 수 있다. Retry-After 또는 기본 30초부터 제한된 지수 대기를 적용하고 자동 재개하지 않는다. 사용자가 재시도할 수 있는 시각을 표시한다. 목록 읽기에도 동일 문맥 제한을 적용한다. 중지는 실행 중 요청이 정리될 때까지 새 작업을 막는다.

수집은 시작 route를 고정하고 매 읽기와 스크롤 전에 확인한다. 결과를 저장하기 전 탭 주소도 확인한다. 문맥이 바뀐 batch는 버린다. Notebook은 origin, notebook ID, authuser 문맥을 fetch 전후 확인한다. 오래된 작업 결과가 다른 노트북 상태에 적용되지 않도록 작업 식별을 확인한다.

## 화면

- 제목, 채널, URL 검색과 표시된 항목 전체 선택을 제공한다.
- 선택 삭제는 검색 밖 선택도 포함한 개수를 알린다. 삭제 취소는 다른 변경을 보존한다.
- 현재 창의 개별 Notebook 탭을 선택할 수 있다. 사용자가 고른 대상을 활성 탭 변경으로 바꾸지 않는다. 사라진 탭은 조용히 다른 탭으로 대체하지 않는다.
- 최신 본문 추출과 실패·미완료 재시도를 구분한다.
- 다시 그려도 사용 중인 체크박스의 키보드 포커스를 보존한다.

## 범위 조정

본문의 패널 종료 후 복구는 이번 변경에 추가하지 않는다. 현재 계정 구분값은 로그인 순번이므로 안정적인 계정 식별자로 볼 수 없다. 본문은 기존처럼 패널 메모리에만 둔다. 최신 추출 실패 시 같은 패널의 이전 성공 본문은 보존한다. 별도 oEmbed 요청도 추가하지 않는다. 이 작업의 metadata 문제는 같은 영상을 수집할 때 빈 정보를 보완하면 해결된다.

이 두 항목은 후보 설계를 검토한 뒤 확정했다. 초기에 검토한 복구 옵션은 구현 범위에서 제외한다.

## 검증

한 구현 담당자가 소스와 테스트를 소유한다. 먼저 저장과 병합 단위를 검증한 뒤 추출과 화면을 연결한다. 테스트는 두 클라이언트 동시 추가/선택/삭제, 500개 경계, worker 재생성, 느린 응답, undo, 최신 추출 실패, 부분/전체 누락, 429, 취소, 문맥 변경을 포함한다. QA adapter는 실제 저장 모듈을 재사용한다.

브라우저 테스트 화면에서 변경 전 metadata와 재추출 문제를 확인했다. 이후 설치된 Chrome 화면 접근은 URL 검증 실패로 자동 제어가 중단됐다. 이 실행에서는 더 이상 브라우저를 제어하지 않는다. 변경 후 실제 화면과 설치 API 검증은 미검증으로 기록하고 로컬 DOM/API 모의 통합 검사를 수행한다.

호스트 권한을 추가하지 않는다. 배포 ZIP에는 extension 파일과 설치 안내만 포함한다. 기존 build-package.py는 별도 임시 폴더에서 실행해 정상 통과했다. 새 버전도 같은 도구로 빌드하고 검증한다.
